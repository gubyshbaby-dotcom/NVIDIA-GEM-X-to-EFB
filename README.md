# NVIDIA GEM-X → Epic Fight (Blender)

Транслятор видео-мокапа **NVIDIA GEM-X** на риг **Epic Fight** в Blender.

GEM-X ([NVlabs/GEM-X](https://github.com/NVlabs/GEM-X)) восстанавливает по обычному
видео движение тела SOMA (77 суставов). Этот репозиторий — аддон **Epic Fight / VIX
0.28.0** (`ef_blender/`), в который добавлен импорт результата GEM-X: одна команда —
и снятое на телефон движение играет на бипеде Epic Fight (Steve/Alex) с контроллерами,
IK и экспортом в `.json` для мода.

```
видео.mp4 ──GEM-X──▶ hpe_results.pt ──Blender: File ▸ Import ▸ NVIDIA GEM-X Motion──▶ риг Epic Fight
                                     └─tools/gemx_to_ef.py (без Blender)──────────────▶ анимация .json для игры
```

## Установка

1. Скачайте `ef_blender-0.28.0.zip` (или соберите: `blender --command extension build
   --source-dir ef_blender --output-dir dist`).
2. Blender 4.2+ → *Edit ▸ Preferences ▸ Get Extensions ▸ ⌄ ▸ Install from Disk…* → zip.

Аддону не нужны torch, numpy или GPU: файл `.pt` читается встроенным безопасным
ридером (см. ниже).

## Шаг 1 — снять движение в GEM-X

```bash
python scripts/demo/demo_soma.py --video myvideo.mp4        # камера двигается
python scripts/demo/demo_soma.py --video myvideo.mp4 -s     # камера на штативе
```

Результат: `outputs/demo_soma/myvideo/hpe_results.pt`. Подходит и ускоренный
`demo_soma_onnx.py`. Советы по съёмке: человек целиком в кадре, без сильных
перекрытий, один человек в кадре.

## Шаг 2 — импорт в Blender

*File ▸ Import ▸ NVIDIA GEM-X Motion to Epic Fight (.pt, .npz, .bvh)* — или
N-панель *Epic Fight ▸ Build ▸ Import GEM-X Motion*. Выберите `hpe_results.pt`.

> **Video rate** — укажите частоту кадров **исходного** видео (30, 60…).
> `hpe_results.pt` её не хранит, а копия `.mp4`, которую демо кладёт рядом,
> всегда перекодирована в 30 fps. Ошибка здесь = ускоренное/замедленное движение.

Что происходит:

* если в сцене нет рига — создаётся тот же риг, что делает *Generate* (контроллеры,
  тело, скин); если риг есть — анимация ложится на него, а прежний клип
  паркуется на заглушённый NLA-трек;
* ключи ложатся на FK-контроллеры и **прореживаются** (см. «Ключи» ниже), затем
  IK-ручки запекаются по результату — любую конечность можно переключить на IK в
  любом кадре, поза не сдвинется (проверено: ≤ 0.1 мм);
* если захват выходит за упоры рига (пресет *Epic Fight* — это ровно диапазон
  штатных клипов мода, а человек, например, сгибает локоть больше 140°), импорт
  выключает у рига *Joint Limits* и пишет об этом предупреждение — иначе экспорт
  молча обрезал бы движение. Опция *Keep joint limits* — обрезать намеренно;
* action получает имя видео; параметры импорта сохраняются в нём (`efb_gemx`);
* создаётся **камера видео** — там, где стояла камера телефона, с тем же
  объективом, а за ней — само видео (копия, которую GEM-X кладёт рядом с
  `hpe_results.pt`). Numpad 0 — и Steve стоит поверх человека кадр в кадр; так
  сразу видно, где риг расходится с видео (см. «Проверка по видео»).

### Параметры импорта

| Группа | Параметр | По умолчанию | Смысл |
|---|---|---|---|
| Source | Video rate | 30 | fps исходного видео (для BVH берётся из файла) |
| | Clip rate | 0 | fps клипа; 0 = как у видео (до 60) |
| | First / Last frame | 0 / −1 | диапазон кадров видео |
| | Smoothing | 0 | гауссово сглаживание, σ в кадрах; 0 — выкл. GEM-X и так гладкий, а фильтр срезает пики быстрых движений: удар при 24 fps длится 2–3 кадра |
| Placement | Root motion | Full path | *Full path* — персонаж идёт по траектории; *In place* — только высота (для зацикленной локомоции) |
| | Face forward | вкл | развернуть так, чтобы в первом кадре смотрел вперёд |
| | Start at origin | вкл | начать в начале координат |
| | Feet on the floor | вкл | опустить так, чтобы ступни бипеда стояли на полу |
| | Person's height | 0 | рост человека в м; 0 — оценить по клипу |
| Keys | Keys | Per bone | *Per bone* / *Key poses* / *Every frame* — см. «Ключи» |
| | Key tolerance | 2° | насколько кость может отойти от захвата между ключами |
| Video camera | Video camera | вкл | камера видео с видео на фоне |
| | Video | — | своё видео для фона; пусто — копия GEM-X рядом с файлом |
| Body | Hands follow the body | 1.0 | кисти туда, где они у человека относительно тела (см. «Удары локтями») |
| | Straighten reaching arms | 1.0 | выпрямлять поднятые руки — удары, дотягивание (см. «Недоразогнутые удары») |
| | Hinge elbows and knees | вкл | локти/колени — чистые шарниры, как у рига (см. ниже) |
| | Wrist to Tool | вкл | поворот кисти → сокет `Tool_R/L` (предмет в руке следует за кистью) |
| | Collarbones | 0.4 | доля поворота ключиц (см. «Удары локтями») |
| | Keep joint limits | выкл | не выключать упоры рига |
| Rig | Build / Body Mesh / Bake IK | Wide / вкл / вкл | как у обычного импорта Epic Fight |

### Ключи

Захват — это ключ на каждом кадре каждого канала: редактировать такое невозможно.
Поэтому после импорта FK-ключи пересобираются в редкие ключи на плавных кривых
(Bezier, Auto Clamped — как при ручной анимации), с гарантией: ни в одном кадре кость
не отходит от захвата дальше **Key tolerance** (проверяется на настоящих кривых
Blender, а не на модели).

| Режим | Что получается | Пример: ходьба 272 кадра / обычное движение 931 кадр, 2° |
|---|---|---|
| **Per bone** (по умолчанию) | у каждой кости только свои нужные ключи | ключ примерно раз в 4 / 11 кадров |
| **Key poses** | одни и те же кадры у всех костей — в Dope Sheet это «позы»-столбцы, их удобно двигать и ретаймить | поза примерно раз в 2–3 кадра: плотнее, т.к. если ключ нужен хоть одной кости, он ставится всем |
| **Every frame** | ключ на каждом кадре, линейно — точная копия захвата | — |

Больше tolerance — меньше ключей (3–5° обычно незаметны: 2° на руке — около 2 см,
треть пикселя Minecraft). Кнопка *Epic Fight ▸ Build ▸ Reduce Keys* прореживает
текущий action ещё раз (например, с другим допуском) — или любой другой клип.
Экспорт в игру от этого не страдает: штатный экспорт видит Bezier-кривые и сам
запекает их плотно.

### Wide ↔ Slim на готовом риге

N-панель *Epic Fight ▸ Body ▸ Build: Wide | Slim*. Риг переключается **на месте**:
две сборки отличаются только положением покоя 42 костей руки (~3 см), так что
переставляются они, пересаживаются Child Of и меняется тело. Всё остальное остаётся:
ключи всех action (и на NLA), настройки, rest-override, прикреплённое оружие, сам
объект. Ключи Epic Fight — это отклонения от покоя, поэтому клип играет на новых руках
так же, как его сыграет игра. IK-запекание текущего action обновляется.
Встроенный скин Steve/Alex меняется вместе со сборкой, свой скин остаётся
(*Keep my skin*). Проверено: результат совпадает с ригом, сгенерированным с нуля
(≤ 10⁻⁶), и переключение туда-обратно возвращает исходный риг.

### «Удары локтями» и руки ниже плеч

Разобрано на настоящем клипе GEM-X (825 кадров). Сам перенос точен: предплечье и
плечо Steve смотрят туда же, куда у SOMA (медиана 0.3–0.7°), а сквозь камеру видео
ноги и корпус ложатся на человека. Руки «ломают» пропорции Minecraft:

* **Ширина плеч.** Корни рук у человека в 16 см от позвоночника, у Steve — в
  37.5 см, в 2.3 раза шире при такой же длине рук. Если копировать только углы,
  кисти, которые человек держит перед грудью, у Steve оказываются снаружи, по
  бокам, — локти торчат в стороны. **Hands follow the body** (по умолчанию 1)
  подтягивает кисть к середине на недостающую ширину плеч — целиком у середины
  груди, ноль на линии плеча, — и заново решает руку двухкостной IK, с локтем,
  повёрнутым как у человека (и «мягким» пределом вытяжения, чтобы локоть не
  дёргался). Руки, отведённые в стороны, не трогаются. 0 — старое поведение.
* **Ключицы.** «Плечо» Epic Fight — кость 0.394 м от центра груди до оси руки,
  ключица человека — 0.155 м: тот же поворот уводил корень руки в 2.5 раза дальше,
  на 5–16 см. **Collarbones = 0.4** (по умолчанию) двигает корень руки ровно на
  столько же, насколько ключица двигает его у человека.
* **Глубина.** Точки на видео GEM-X (`0_kp2d77_overlay.mp4`) — это 2D, они
  выглядят верно всегда. Глубину (к камере/от камеры) одиночная камера оценивает
  хуже всего; рука, ушедшая вперёд, в кадре выглядит так же. 3D-результат GEM-X
  показывает в `<видео>_1_incam.mp4` / `_2_global.mp4`. Для ударов это разобрано
  ниже.

### Недоразогнутые удары

Разобрано на боксёрском клипе (128 кадров, джебы и кроссы по груше). На видео рука
в момент удара прямая, а в 3D у GEM-X согнута: на пике левого джеба (кадр 52)
27°, на пиках правых (кадры 58, 59, 73) — 52°, 60° и 49°. Дело в глубине: плечо
лежит в плоскости кадра, а предплечье GEM-X наклоняет к камере на 40–70 % его
длины. В кадре такая рука выглядит почти прямой (10–28°), и 2D-точки верны, но в
3D локоть согнут. В 0.27 сверху добавлялось сглаживание σ=1: оно срезало пик
удара, и на риге выходило 35°, 69°, 71° и 62°.

**Straighten reaching arms** (по умолчанию 1):

* **По камере.** GEM-X сохраняет тело дважды — в мире и в координатах камеры, —
  поэтому известно, куда смотрит камера в каждом кадре. У поднятой руки
  предплечье сохраняет своё направление *в кадре*, а наклон к камере или от неё
  выбирается тот, при котором рука согнута меньше всего. Поверх видео риг
  по-прежнему совпадает с человеком, а удар выпрямляется.
* **По кривой.** Оставшийся изгиб меньше 90° дополнительно раскрывается
  (27°→14°, 45°→34°, 60°→53°). Прямой угол и больше не трогается. Для файлов
  без копии «в камере» (BVH) работает только это.
* **Только поднятые руки.** Плечо должно быть поднято от корпуса на 70° и больше
  (у ударов 70–105°); ниже 45° ничего не меняется. Ходьба (10–50°), опущенные
  руки и махи остаются как в захвате. Гард (локоть 100° и больше) тоже не
  трогается.

Итог на этом клипе: кадр 52 — 0° (было 35°), 58 — 6° (было 69°), 59 — 11°
(было 71°), 73 — 13° (было 62°); гард 105–135° без изменений. 0 — выключить.

### Проверка по видео

После импорта: Numpad 0 (вид через камеру видео), листайте таймлайн. Steve
масштабирован по длине ног, поэтому ноги и таз ложатся на человека точно, а голова
и руки больше — это пропорции Minecraft. Если в каком-то кадре поза расходится с
человеком, а в `_1_incam.mp4` GEM-X — нет, пришлите номер кадра. Фон виден только в
окне камеры, в рендер не попадает. Если «Clip rate» отличается от «Video rate»,
видео и клип разойдутся по времени.

## Шаг 3 — в игру

*File ▸ Export ▸ Epic Fight Animation (.json)* — штатный экспорт аддона.

Или без Blender вовсе (обычный python 3.8+, без зависимостей):

```bash
python tools/gemx_to_ef.py outputs/demo_soma/myvideo/hpe_results.pt --fps-in 30
# -> outputs/demo_soma/myvideo/myvideo_epicfight.json
```

Полезные ключи: `--in-place`, `--slim` (Alex), `--height 1.80`, `--start/--end`,
`--fps 60`, `--smooth 1`, `--hands 0` (только углы), `--extend 0` (не выпрямлять удары),
`--clavicle 1`, `--no-hinge`,
`--no-tools`, `--describe` (показать, что лежит в файле). CLI пишет все 20 суставов, включая маркеры `Elbow_*/Knee_*` со
сдвигом шва, как в штатных клипах. Ключи прореживаются линейно (`--keys per-bone`,
`--key-tolerance 0.5`): игра интерполирует линейно, и отклонение проверено её же
интерполяцией; `--keys all` — каждый кадр. С `--keys all` результат совпадает с
экспортом из Blender (≤ 0.0001°).

## Другие источники SOMA

* `.bvh` со скелетом SOMA — BONES-SEED, NVIDIA Kimodo (`--bvh`), экспорт
  soma-retargeter;
* `.npz` / `.pt` с ключами `global_orient`, `body_pose`, `transl` (или `poses`).

## Как это работает

* **Чтение `.pt` без torch** (`efb/tensorio.py`). `torch.save` — это zip: pickle
  с описанием + сырые массивы. Pickle не исполняется «как есть»: разрешён только
  фиксированный список имён (контейнеры, сборка тензоров torch, массивы numpy),
  всё остальное превращается в инертную заглушку. Открытие файла не может
  выполнить код.
* **SOMA** (`efb/soma.py`, `efb/data/soma77.json`). Позы GEM-X — в стиле SMPL,
  относительно T-позы: SOMA собирает сустав как `orient[p]⁻¹·pose[j]·orient[j]`,
  ориентиры сокращаются, и мировой поворот сустава от T-позы —
  `G[j] = G[parent]·R(pose[j])`. Больше ничего (модель тела, меш, torch) не нужно.
  Таблица T-позы сгенерирована `tools/make_soma_table.py` из ассетов NVIDIA.
* **Ретаргет** (`efb/gemx.py`). Оба скелета переводятся в пространство арматуры
  (Z вверх, бипед смотрит на +Y). Кость Epic Fight копирует поворот «своего»
  сустава SOMA: `pose = G · align · rest`, где `align` для рук/ног разворачивает
  опущенные руки бипеда в T-позу SOMA. Колени и локти решаются как шарниры:
  верхняя кость поворачивается вокруг своей оси, пока шарнир не встанет по
  нормали к плоскости конечности, нижняя сгибается только по оси X (как требует
  пин рига). Пронация предплечья при этом не теряется — она уходит в `Tool_*`.
  Траектория таза масштабируется отношением длины ног (0.761 м у бипеда против
  ~0.93 у человека), клип опускается на пол по ступням самого бипеда.
* **Глубина поднятых рук** (`_Solver._depth`). Луч камеры к локтю переводится из
  координат камеры в мир через два поворота таза (`R = G_incam·G_world⁻¹`).
  Предплечье поворачивается в плоскости «своё направление в кадре + луч»
  к направлению, ближайшему к плечу, — это самая прямая рука, которую
  допускает кадр.
* Результат — обычный документ анимации Epic Fight (формат `attributes`), который
  идёт через штатный импорт аддона.

## Ограничения

* У бипеда Epic Fight нет пальцев, лица и стоп — эти суставы SOMA не переносятся.
* Форма тела (identity/scale) не используется — только движение скелета.
* `hpe_results.pt` не хранит fps — его задаёте вы.
* ONNX-демо GEM-X не «приземляет» клип; тогда рост не оценивается (берётся
  средний 1.77 м, задайте *Person's height*), а пол находится по ступням бипеда.
  Если там подставлены координаты камеры (Y вниз), клип переворачивается
  автоматически.

## Проверки

```bash
python3 -m unittest discover -s tests -v          # 34 теста, без Blender и torch
blender -b --factory-startup --python-exit-code 1 \
        --python tests/blender_gemx.py -- tests/data/squat_hpe_results.pt
```

Blender-гейт (4.5 LTS): импорт на настоящий риг; поза deform-костей = ретаргет
(≤ 6·10⁻⁶ м) на каждом кадре; ступни на полу; IK-переключение не двигает позу;
штатный экспорт = CLI-json; прореживание держит допуск на каждом кадре, *Key poses*
выстраивает все кости в одни кадры; Wide→Slim = свежий Slim-риг, ключи и позы
не меняются, Slim→Wide возвращает исходный. Проверено на реальных клипах SOMA (ходьба, прыжок,
танец, удар ногой, присед) и GEM-X (два клипа с ударами руками).
